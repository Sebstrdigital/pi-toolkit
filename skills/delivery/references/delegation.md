# Delegation

A clear task execution request is sufficient authority; no separate mode selection or Agreement confirmation. A proposal alone is not. Give the worker purpose, outcome, constraints/exclusions, acceptance, relevant rules/source and current candidate. A compact text packet is enough. No mandatory reading manifests or read receipts. File lists are pointers unless the user explicitly restricted them; necessary supporting files remain within the requested outcome.

Choose the roles needed for the task, not a compulsory three-role cycle per slice. Fixed builder, no-edit validator, inspection-only reviewer and read-only Scout grants remain available. Preserve requested independent gates; the lead alone inspects and accepts.

Use the installed tmux controls with a persistent parent session. Models follow configured routing; saved grants/model/context policies remain pinned. Authority references describe the user's existing request, not another approval to obtain. Developer takes compact text or its legacy structured packet; selection is optional compatibility metadata. See ../../../docs/lean-workflows.md.

Independent tasks can run concurrently in distinct linked worktrees via subagent/developer cwd. Same-workspace ownership is exclusive, including pause/wait; use current checkout or an existing linked worktree, not an arbitrary path. No nested workers. Do not blindly merge, reset or clean another person's work.

Results/questions arrive automatically; do not poll. Use exact owned names and matching runId/questionId for answers. Pause preserves the pane; rearm supplies new in-scope work. Resume carries original authority references without asking the user again. Changed permission/outcome needs a real decision.

Ordinary compiler/test/harness corrections and actionable review findings authorize diagnosis and repair within the task. Do not invent repair caps or minute pools. Optional assignment binds user-requested cumulative execution limits; repairAttempts is optional, never mandatory bookkeeping or a quota for each compiler error. Existing declared limits remain binding. A terminal same-role replacement uses original authority, partial-source identities, findings, reconciled resources and remaining declared allowance. One replacement is supported, as with TAKT's stronger worker retry; useful same-worker repairs are not replacement attempts.

New workers load project context/skills/templates/themes; executable extension/MCP discovery remains denied without a trust mechanism. This is not an OS sandbox. Legacy saved snapshots retain all original denials; do not widen them on resume.

Return concise changed paths/candidate, actual checks/exits, gaps, decisions and evidence pointers. Keep raw logs on disk. Reuse unchanged evidence; renew affected checks/review and final integrated evidence proportionately. Stop for actual new authority, explicit exhausted limits or demonstrated no progress, not another red check. New private-data access, live application control and destructive/outward actions need applicable permission. Finish with the candidate, consolidated manual checks and honest gaps.
